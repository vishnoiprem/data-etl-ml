### Q17: Challenging technical problem on GCP

**STAR Answer (2 min):**
```
SITUATION: Dataflow job failing OOM at 2am daily. [5TB shuffle], [200 workers], deadline next morning for [board report].

TASK: Root cause + fix without full reprocess.

ACTION:
1. ANALYZED: Worker logs → skewed key (user_id=NULL = 40% records). Single worker getting 2TB shuffle.
2. MITIGATION: 
   - Salting: user_id || '_' || CAST(RAND()*100 AS INT64) for NULL keys
   - Custom partitioner: Separate NULL keys to dedicated partition
   - Enabled Shuffle Service (managed shuffle on SSD)
3. BACKFILL: Only affected partitions via partition filter (not full reprocess)
4. PREVENTION: Added skew detection to CI/CD pipeline (alert if any key >5% of data)

RESULT: Job completed in [4 hours] (was 14hr+OOM). Zero failures since. Pattern documented in best practices repo.
```
