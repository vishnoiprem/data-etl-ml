Produce an onboarding brief for someone who has never seen this repository. This
is for a new human *or* a fresh agent session — the output should let the reader
make a correct first edit without asking a question.

Read broadly but cheaply: use Glob and Grep to find structure, then Read only the
files that turn out to matter. Do not dump the whole repository into context.

Cover these sections, in this order:

**1. What this is.** Two or three sentences. What the product does, who uses it.

**2. Stack, with versions.** Every language, framework, and datastore you can
find evidence of. Cite the file you found it in.

**3. Directory layout.** The real tree, with a one-line purpose per directory.
Call out anything surprising — a directory named `utils` that actually contains
SQL, or a `legacy/` tree that is still imported from.

**4. The five most important files.** Rank by "how often does someone edit this?"
Each with its path and what it owns.

**5. Conventions that are enforced.** Formatting, lint rules, commit message
format, test layout, naming. Only report conventions you can point to in config.

**6. Commands.** How to install, run, test, lint, build. Real commands from the
Makefile / package.json / pyproject.toml — not invented ones.

**7. Gotchas.** The things that will bite a newcomer. Trace imports if needed.
Look for: circular imports, environment variables read at import time, global
mutable state, code generated by a tool that must not be hand-edited, and
anything marked TODO/FIXME/HACK.

**8. Where to start.** If a new contributor had one afternoon, what should they
read, in what order?

Be specific and cite paths. If you cannot determine something, say "could not
determine" rather than guessing — a wrong onboarding brief is worse than an
incomplete one, because it will be trusted.
