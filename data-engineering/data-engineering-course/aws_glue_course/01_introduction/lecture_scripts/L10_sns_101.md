## What this lecture covers

- SNS = Simple Notification Service. The pub/sub messaging pattern. Topics, publishers, subscribers, and the 6 subscriber types.

## Narration

> "SNS is the AWS pub/sub service. The pattern is simple: a publisher sends a message to a *topic*; the topic fans out the message to all *subscribers*. The 6 subscriber types are: SQS queue, Lambda function, HTTP/S endpoint (a webhook), email address, SMS message, and mobile push notification. For Glue, the most common use is an SNS topic that fires when a Glue Job succeeds or fails — you subscribe an email or a Lambda function. The key insight: SNS fans out *independently* to each subscriber. If one subscriber fails (e.g., a Lambda throws), the others still get the message. This is different from SQS, which is a queue (FIFO or standard) and guarantees delivery to one consumer. SNS guarantees fan-out; SQS guarantees delivery."

## Key concepts

- **Topic**: the channel that messages are published to. Has an ARN.
- **Publisher**: sends messages to a topic. Uses `sns:Publish` permission.
- **Subscriber**: receives messages from a topic. Each subscriber type has its own protocol (email, https, sqs, lambda, sms, application).
- **Fan-out**: one message published to a topic is delivered to every subscriber, independently.
- **Delivery retry**: SNS retries failed deliveries (e.g., HTTP 500) with exponential backoff. After the retry policy is exhausted, the message is dropped, or sent to a DLQ if configured.
- **Access control**: SNS topics have resource-based policies (like S3 bucket policies). The topic's policy controls who can publish and who can subscribe.
