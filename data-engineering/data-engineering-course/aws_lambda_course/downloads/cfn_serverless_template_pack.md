> **Source of truth:** `13_cloudformation_serverless/code/templates/`
> **Format:** this file is the source for `downloads/cfn_serverless_template_pack.zip` (the zip is generated by `scripts/build_cfn_pack.py` in production).
> **What ships in the zip:** every YAML template below + the two Lambda zips from `13_cloudformation_serverless/code/lambdas/`.

This pack contains the five standalone CloudFormation templates that build up
the section 13 serverless use case (API Gateway + Lambda + S3) one layer at a
time. Each template is a runnable `aws cloudformation deploy` unit and is
labeled with the lecture that introduces it.

## Files in the pack

| # | File | Lecture | Purpose |
|---|---|---|---|
| 1 | `01_minimal_s3_bucket.yaml` | L62 | The smallest possible useful S3 bucket: versioning on, default encryption (SSE-S3), `BlockPublicAccess: BLOCK_ALL`, a `Retain` removal policy, and a `Tag` block. Useful as a sandbox bucket and as the dependency for the next four templates. |
| 2 | `02_lambda_execution_role.yaml` | L63 | A least-privilege IAM role for the Lambdas in this section. ## Deploy order

The templates are numbered to be deployed in order; each one is also a usable
sandbox on its own. The full chain is:

```bash
# 0. Bootstrap: create a CFN-managed asset bucket
aws cloudformation deploy \
  --stack-name cfn-assets \
  --template-file 01_minimal_s3_bucket.yaml

# 1. Role (depends on bucket name)
export BUCKET_NAME=$(aws cloudformation describe-stacks \
  --stack-name cfn-assets \
  --query 'Stacks[0].Outputs[?OutputKey==`BucketName`].OutputValue' --output text)
aws cloudformation deploy \
  --stack-name cfn-role \
  --template-file 02_lambda_execution_role.yaml \
  --parameter-overrides BucketName=$BUCKET_NAME \
  --capabilities CAPABILITY_NAMED_IAM

# 2. Package + deploy the Lambda (depends on role ARN + bucket name)
aws cloudformation package \
  --template-file 03_lambda_function.yaml \
  --s3-bucket $BUCKET_NAME \
  --output-template-file /tmp/03_lambda_function.packaged.yaml
aws cloudformation deploy \
  --stack-name cfn-lambda \
  --template-file /tmp/03_lambda_function.packaged.yaml \
  --capabilities CAPABILITY_NAMED_IAM

# 3. REST API resources only
aws cloudformation deploy \
  --stack-name cfn-api-resources \
  --template-file 04_rest_api_resources.yaml

# 4. Methods + deployment (replaces 04 if you want a single stack)
aws cloudformation deploy \
  --stack-name cfn-api-full \
  --template-file 05_method_deployment.yaml \
  --parameter-overrides \
      GetLambdaName=cfn-lambda-GetFunction \
      PutLambdaName=cfn-lambda-PutFunction \
      RoleArn=$(aws cloudformation describe-stacks --stack-name cfn-role \
        --query 'Stacks[0].Outputs[?OutputKey==`RoleArn`].OutputValue' --output text) \
  --capabilities CAPABILITY_NAMED_IAM
```

The end-to-end demo flow (without packaging) for the **single-stack** path is in lecture L68; with parameters and metadata, in L69–L70.

## How to use this pack

- **Linear:** deploy templates 01–05 in order to reproduce the lecture.
- **Reference:** template 05 is the **single-stack** version of the whole
  architecture — it's a good starting point for any project that needs a
  REST API in front of two Lambdas talking to a single bucket.
- **Assignment 5** (the "from scratch" assignment) intentionally asks you
  *not* to open these files. They are here to check your work against.

## Cleanup

```bash
for s in cfn-assets cfn-role cfn-lambda cfn-api-resources cfn-api-full; do
  aws cloudformation delete-stack --stack-name $s
done
aws s3 rb s3://<your-cfn-assets-bucket> --force
```

The asset bucket is **not** deleted by `aws cloudformation delete-stack` if
it still contains objects; empty it first.
