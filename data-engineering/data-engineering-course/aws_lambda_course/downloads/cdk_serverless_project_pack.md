> **Author:** Prem Vishnoi <prem.vishnoi@example.com>

> **Format:** this file is the source for `downloads/cdk_serverless_project_pack.zip` (the zip is generated by `scripts/build_cdk_pack.py` in production and excludes `node_modules/`, `cdk.out/`, and `*.js`).
> **What ships in the zip:** the entire `12_cdk_v2_serverless/code/` tree (minus the artifacts) so a student can `npm install && cdk deploy` from scratch.

This pack contains the AWS CDK v2 (TypeScript) project that re-implements
the section 13 serverless use case in code. The same architecture is in
section 13 (CloudFormation YAML) — this is the CDK equivalent.

## Stack overview

The stack (`ServerlessStack`) provisions:

- 1 S3 bucket (`serverless-objects-<acct>-<region>`) — versioned, SSE-S3, public access blocked, TLS enforced, `autoDeleteObjects: true`, `removalPolicy: DESTROY`.
- 1 IAM role (`ServerlessStack-LambdaExecutionRole`) — assumed by `lambda.amazonaws.com`, inline policy scoped to `s3:GetObject` + `s3:PutObject` on the bucket ARN.
- 2 Lambda functions (Node.js 20, 256 MB, 30 s, log retention 7 days) bundled from `lambda/` via esbuild:
  - `GetObjectFn` — handler `get-object.handler`
  - `PutObjectFn` — handler `put-object.handler`
- 1 REST API (`Serverless Objects API`) — `GET /objects/{key}` and `PUT /objects/{key}` with `AWS_PROXY` integration, CORS preflight enabled.

Exports:

- `ObjectsBucketName`
- `ApiUrl`

### `bin/serverless-app.ts`

CDK app entry point. Instantiates `ServerlessStack` with the `DefaultStackSynthesizer` (asset bucket + roles created by `cdk bootstrap`). Tags every taggable resource with `Project`, `Section`, `ManagedBy`. The stack's `description` is included in the synthesized CloudFormation `Description` field.

### `lib/serverless-stack.ts`

The stack itself. Builds the resources in this order so cross-resource `Ref`/`GetAtt` resolve cleanly: bucket → role → Lambdas → API. The IAM policy is inline (not managed) so it is co-located with the role and the resource ARNs are obvious. The Lambda bundle uses `lambda.Code.fromAsset(join(__dirname, '..', 'lambda'))` — esbuild runs automatically and produces a tiny zip with only the imports the handler actually references. CORS is enabled via the L2 `defaultCorsPreflightOptions` so the API handles `OPTIONS` automatically.

### `lambda/get-object.ts`

Node 20 handler for `GET /objects/{key}`. Imports `S3Client` and `GetObjectCommand` from `@aws-sdk/client-s3` (v3 modular SDK). Reuses one `S3Client` instance across invocations (the Lambda execution environment freezes the module graph). Returns 400 on a missing path param, 404 when S3 raises `NoSuchKey`, and 500 on any other error.

### `lambda/put-object.ts`

Node 20 handler for `PUT /objects/{key}`. Reads `event.body`, calls `PutObjectCommand` with the bucket name from `process.env.BUCKET_NAME`. Content-Type is taken from the request header, falling back to `application/octet-stream`. Returns 200 with a small JSON confirmation.

## How to use this pack

```bash
unzip cdk_serverless_project_pack.zip -p | tar -x # (zip is the production artifact)
cd cdk_serverless_project_pack/
npm install
npx cdk bootstrap                  # one-time, per account/region
npx cdk synth                      # emits CloudFormation to cdk.out/
npx cdk diff                       # compare to deployed state
npx cdk deploy                     # deploys; prints ApiUrl
```

Then:

```bash
API=$(aws cloudformation describe-stacks --stack-name ServerlessStack \
  --query 'Stacks[0].Outputs[?OutputKey==`ApiUrl`].OutputValue' --output text)
curl -X PUT -H "Content-Type: application/json" -d '{"hello":"world"}' "$API/objects/foo"
curl -i "$API/objects/foo"
```

Cleanup:

```bash
npx cdk destroy
```

## Notes

- The CDK app uses **esbuild** (via `fromAsset`) instead of `node-bundle` or manual zipping. esbuild is the default bundler since CDK v2.20 and produces a zip that is typically < 1 MB.
- The IAM policy is **inline** (in `lib/serverless-stack.ts`) rather than a managed policy. This keeps the policy and the role co-located, but does not allow reuse across stacks — if you need that, extract it into a shared `iam.ManagedPolicy` construct.
- The CORS settings (`defaultCorsPreflightOptions.allowOrigins: ['*']`) are intentionally permissive for a sandbox. In production, replace with a specific origin list and `allowCredentials: true`.
- `cdk.context.json` is shipped in the pack for reproducibility. Delete it if you change regions or accounts; CDK will re-resolve.

## Stretch (not in this pack, but easy to add)

- Convert the inline policy to a `iam.ManagedPolicy` and import it in a second stack.
- Add a `wafv2.CfnWebACLAssociation` for a rate-based rule.
