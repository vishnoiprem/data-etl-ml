## 1. The three layers: client vs resource vs session

```
Session  (credentials, region, profile)
   ├── Client("s3")     — low-level, 1:1 with AWS API, returns dicts
   └── Resource("s3")   — high-level object graph (s3.Bucket, s3.Object)
```

Rule of thumb:

| Task | Use |
|---|---|
| Quick one-shot list / get / put | **Client** |
| Iteration over a known-bounded set with rich object methods (`.load()`, `.delete()`, `.wait_until_exists()`) | **Resource** |
| Anything paginated with custom logic | **Client + paginator** |
| Cross-account / multi-region | **Multiple sessions** |

## 2. Sessions

```python
import boto3

# Default
s = boto3.Session()
client = s.client("s3")

# Named profile
s = boto3.Session(profile_name="prod-admin", region_name="eu-west-1")

# Explicit credentials (avoid in prod — use IAM roles or SSO)
s = boto3.Session(
    aws_access_key_id=...,
    aws_secret_access_key=...,
    aws_session_token=...,  # only for STS-assumed creds
)

# Cross-region: one session per region
for region in ("us-east-1", "eu-west-1"):
    s = boto3.Session(region_name=region)
    client = s.client("ec2")
    print(region, client.describe_regions()["Regions"])
```

## 3. Pagination

### Client + paginator (recommended)

```python
s3 = boto3.client("s3")
paginator = s3.get_paginator("list_objects_v2")

for page in paginator.paginate(Bucket="my-bucket", Prefix="logs/", PaginationConfig={"PageSize": 100}):
    for obj in page.get("Contents", []):
        print(obj["Key"], obj["Size"])
```

Common paginators: `list_objects_v2`, `list_buckets` (does not paginate, returns everything), `describe_instances`, `list_tables`, `scan`, `list_functions`, `list_users`, `describe_db_instances`, `list_log_groups`, etc. The full list: `client.can_paginate("op_name")`.

### Resource (only for resources that support it)

```python
s3 = boto3.resource("s3")
bucket = s3.Bucket("my-bucket")
for obj in bucket.objects.all():           # auto-paginates
    print(obj.key, obj.size)
for obj in bucket.objects.filter(Prefix="logs/"):
    ...
for obj in bucket.objects.limit(50):
    ...
```

`limit()` truncates without warning. Use `PaginationConfig={"MaxItems": N}` on the client for safe truncation.

### Custom paging keys

```python
paginator = client.get_paginator("list_objects_v2")
paginator = paginator.paginate(
    Bucket="my-bucket",
    PaginationConfig={
        "PageSize": 100,
        "MaxItems": 1000,
        "StartingToken": None,
    },
)
```

To resume, pass the last `NextToken` from the previous iteration back as `StartingToken`.

## 4. Waiters

Waiters block until a resource reaches a desired state. They poll until success or timeout.

```python
# Built-in
waiter = s3.get_waiter("bucket_exists")
waiter.wait(Bucket="my-bucket")

ec2 = boto3.client("ec2")
ec2.get_waiter("instance_running").wait(InstanceIds=["i-12345"])
ec2.get_waiter("instance_terminated").wait(InstanceIds=["i-12345"])

ddb = boto3.client("dynamodb")
ddb.get_waiter("table_exists").wait(TableName="my-table")
```

Timeouts: `waiter.wait(..., WaiterConfig={"Delay": 10, "MaxAttempts": 60})`.

Custom waiters: define a JSON file in `~/.aws/waiters/` or ship one in your package.

## 5. Error handling

```python
from botocore.exceptions import ClientError, BotoCoreError, WaiterError

try:
    s3.head_object(Bucket=b, Key=k)
except ClientError as e:
    code = e.response["Error"]["Code"]
    if code in ("NoSuchKey", "404"):
        return None
    if code == "AccessDenied":
        raise PermissionError(code) from e
    raise
except BotoCoreError:
    # network / parse / credential errors
    raise
```

The canonical retryable codes (handled automatically by the SDK's default retry mode `standard`):

```
ThrottlingException, RequestThrottled, RequestLimitExceeded,
PriorRequestNotComplete, Throttling, TooManyRequests,
ProvisionedThroughputExceededException, TransactionInFlightException,
RequestTimeout, RequestTimeoutException, IDPCommunicationError,
Unavailable, InternalError, InternalFailure, ServiceUnavailable,
ServiceUnavailableError, SlowDown
```

Retry config:

```python
from botocore.config import Config

cfg = Config(
    retries={"max_attempts": 10, "mode": "adaptive"},  # or "standard"
    connect_timeout=5,
    read_timeout=60,
    user_agent_extra="my-app/1.0",
)
client = boto3.client("s3", config=cfg)
```

`adaptive` retry mode (default since 2024) adds client-side throttling on top of `standard`'s exponential backoff. Use `standard` for predictable behavior.

## 6. Multi-region, multi-account

```python
# Assume a role in another account, then create a session with those creds
import boto3, json

sts = boto3.client("sts")
resp = sts.assume_role(
    RoleArn="arn:aws:iam::222222222222:role/CrossAccountReader",
    RoleSessionName="my-session",
)
creds = resp["Credentials"]
target = boto3.Session(
    aws_access_key_id=creds["AccessKeyId"],
    aws_secret_access_key=creds["SecretAccessKey"],
    aws_session_token=creds["SessionToken"],
    region_name="us-east-1",
)
ec2 = target.client("ec2")
```

For cross-region from the same account, just instantiate a new `Session(region_name=...)`.

## 7. Resource vs Client — decision tree

```
Need to iterate over objects with attribute access (obj.size, obj.key)?
   └── yes ── Resource
   └── no  ── Client

Need waiters?
   └── yes ── Client (waiters are on the client)
   └── no  ── either

Need pagination over an op that the Resource doesn't expose?
   └── yes ── Client + paginator
   └── no  ── either

Need fine-grained control over retries, timeouts, or HTTP?
   └── yes ── Client (with Config(...))
   └── no  ── either
```

## 8. Common one-liners

```python
# S3
boto3.client("s3").upload_file("local.csv", "bucket", "key")
boto3.client("s3").download_file("bucket", "key", "local.csv")

# DynamoDB
ddb = boto3.resource("dynamodb")
table = ddb.Table("users")
table.put_item(Item={"pk": "u1", "name": "alice"})
table.get_item(Key={"pk": "u1"})["Item"]

# Lambda
fn = boto3.client("lambda")
fn.invoke(FunctionName="my-fn", Payload=b'{"k":"v"}')

# STS — useful for "who am I"
print(boto3.client("sts").get_caller_identity())
```

## 9. Testing with `moto`

```python
from moto import mock_aws

@mock_aws
def test_list_buckets():
    boto3.client("s3").create_bucket(Bucket="x")
    boto3.client("s3").create_bucket(Bucket="y")
    names = [b["Name"] for b in boto3.client("s3").list_buckets()["Buckets"]]
    assert sorted(names) == ["x", "y"]
```

`moto` 5.x renamed `@mock_s3` etc. to `@mock_aws` (which mocks all supported services). The old decorators still work but warn.

State is per-decorator; tests using a class-level `@mock_aws` share state — use method-level mocks for isolation.

## 10. Performance tips

- **Reuse sessions and clients** — they're thread-safe and socket-pooled.
- Set `Config(max_pool_connections=50)` for high-fanout scripts.
- Use **paginators** with `PageSize` for memory-bounded iteration over large buckets/tables.
- For S3 **batch** deletes, use `s3.delete_objects(Delete={"Objects": [...]})` with up to 1,000 keys per call.
- For DynamoDB **batch writes**, use `batch_writer()` (Resource API) — it auto-retries unprocessed.
- Set **larger timeouts** for streaming workloads; default `read_timeout=60` may be too low for 1 GB downloads.
