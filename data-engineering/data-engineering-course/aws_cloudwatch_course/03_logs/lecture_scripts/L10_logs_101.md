## Key terms

- **Log group** — a bucket of log streams that share a retention policy.
  Naming convention is `/<service>/<component>`, e.g. `/aws/lambda/my-fn`.
- **Log stream** — an ordered sequence of log events. Typically one per
  instance, container, or function.
- **Retention** — how long log events are kept. Values: 1, 3, 5, 7, 14,
  30, 60, 90, 120, 150, 180, 365, 400, 545, 731, 1827, 2192, 2557, 2922,
  3288, 3653 days, or "Never expire" (default).
- **Metric filter** — a regex on incoming log events that turns them
  into a CloudWatch metric (covered in L13).
- **Subscription filter** — a real-time stream of matching events to
  Kinesis / Firehose / Lambda (covered in section 6).

## Lecture

CloudWatch Logs is organised into a 2-level hierarchy:

```
Log group  /aws/lambda/checkout-api
   ├── Log stream  2026/10/10/[$LATEST]abc123
   ├── Log stream  2026/10/10/[$LATEST]def456
   └── Log stream  ...
```

A **log group** is the unit of:

- **Retention** — set once per group, applied to all streams in it.
- **IAM permissions** — you grant `logs:GetLogEvents` on a group.
- **Subscription filters** — you attach a filter to a group.

A **log stream** is the unit of:

- **Ordering** — events inside a stream are ordered by timestamp.
- **Sequence token** — used for safe concurrent `put_log_events`.

### Recommended naming

| Resource | Pattern | Example |
|---|---|---|
| Lambda function | `/aws/lambda/<fn-name>` | `/aws/lambda/checkout` |
| ECS container | `/ecs/<svc-name>` | `/ecs/payments` |
| Custom app | `/<env>/<service>` | `/prod/api` |
| CloudWatch agent | `/aws/ec2/<instance-id>` | `/aws/ec2/i-0abc` |

### Retention — pick deliberately

The default retention is **"Never expire"** which means **forever**.
At $0.03 / GB-month, that's a surprisingly large bill for chatty
services.

Practical defaults:

| Log type | Recommended retention |
|---|---|
| Production Lambda (debugging) | 30 days |
| Production application (debugging) | 30 days |
| Compliance / audit | 7 years (1827 days) |
| Dev / staging | 7 days |
| High-volume access logs | 3 days, then export to S3 |

```python
logs = boto3.client("logs")
logs.put_retention_policy(logGroupName="/myapp/api",
                          retentionInDays=30)
```

### A note on agent / driver setup

CloudWatch Logs can be written to in three ways:

1. **AWS SDK / `boto3`** — direct API call (used in section 3).
2. **CloudWatch Logs agent / unified agent** — for EC2 / on-prem
   instances.
3. **Lambda's built-in integration** — Lambda's stdout / stderr
   automatically go to `/aws/lambda/<fn-name>`. No code required.

## Hands-on

In your AWS account:

1. *CloudWatch → Logs → Log groups* — find the log group for any
   Lambda function.
2. Note the **retention** column. If it says "Never expire", set it
   to 30 days:

```bash
aws logs put-retention-policy \
    --log-group-name /aws/lambda/<your-fn> \
    --retention-in-days 30
```
