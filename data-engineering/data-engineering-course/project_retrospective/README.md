# Project Retrospective Questions — A Practical Guide for Engineering Managers

> **1 module · 6 lessons · 2 videos · ~4 hours of focused practice**
>
> **Author:** [Prem Vishnoi](https://medium.com/@premvishnoi) · <pvishnoi@avilx.com>
>
> **Companion articles:** [medium.com/@premvishnoi](https://medium.com/@premvishnoi)

The "Project Retrospective" question is the **single most
under-prepared question in the EM interview loop.** Most
candidates walk in with a vague "tell me about a project"
story that lacks structure, lacks numbers, and lacks a clear
takeaway. They get downleveled — not because the project was
small, but because the *telling* of it was small.

This track fixes that.

A Project Retrospective (PR) question is the EM-specific
variant of the general "tell me about a project" prompt.
The interviewer is testing for **judgment, learning,
self-awareness, and the ability to lead a technical effort
to a measurable outcome** — the four signals that most
clearly separate an M3 from an M4, an E5 from an E6, an
L5 from an L6. It's a focused, 5-minute window into how
you think, decide, and grow.

By the end of this track you will have:

- 3 fully-written, 5-minute retrospectives on real projects
  in your career (the capstone)
- A working knowledge of the 5 categories of retrospective
  topics
- A structure (Context → Approach → Outcome → Lessons →
  What I'd Do Differently) that fits any project
- A rehearsed 5/3/90-second version of each retrospective
- A list of 8-10 common PR pitfalls and how to avoid them

## What's in this track

**Prose-only, with one capstone.** Every lesson is a
Markdown file you read and act on. The capstone is writing
3 retrospectives on your own projects — the artifact that
moves the needle.

**Pattern-based.** Every lesson is built around patterns that
repeat across companies: Meta, Google, Amazon, Stripe,
Airbnb, the AI labs, the big banks. Once you see the
pattern, you stop being surprised by the question.

**Calibrated for senior+.** The audience is candidates
interviewing for **M3/M4 (Meta), L5/L6 (Google), Senior/Staff
(most), Staff/Principal (Netflix), and Senior/Principal
EM** roles. The framing is "be seen as a senior EM" — see
Module overview.

## How to use this track

**Week 1 — Read in order (3-4 hours).** Read Lessons 01-04
in one sitting. You'll have the mental model, the
structure, and the rehearsal mechanics by Sunday. Then read
Lesson 05 carefully — the worked example — and Lesson 06
to internalize the pitfalls.

**Week 2 — Mine and write (4-6 hours).** Use the framework
in Lesson 02 to mine 10-15 PR candidates from your
career. Pick 3. Write each one in the 5-minute format
from Lesson 03. Use Lesson 06 as your quality checklist.

**Week 3 — Rehearse (2-3 hours).** Use Lesson 04 to
rehearse each retrospective in 5/3/90-second versions.
Record yourself. Listen. Cut the filler. Iterate.

By the end of week 3, you should be able to answer any
Project Retrospective question — "tell me about a project
you led," "what's the hardest project you've worked on,"
"walk me through a re-platforming effort" — with a clean,
5-minute retrospective that has specific numbers, an
honest failure beat, clear lessons, and a real "what I'd
do differently" closer.

## A note on the prose-only format

There is intentionally **no code, no `app.py`, no `pytest`**
in this track. A Project Retrospective is a *craft* — like
writing, like public-speaking, like sales. You can't run a
unit test on whether your retrospective lands. You can only
practice, get feedback, iterate.

So: **read the lesson. Write the retrospective. Rehearse
it out loud. Get a friend to listen. Repeat.** That's the
entire workflow.
