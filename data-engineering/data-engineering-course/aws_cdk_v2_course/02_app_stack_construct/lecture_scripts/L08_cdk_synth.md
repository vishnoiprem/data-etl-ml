# L08 — `cdk synth` — Turning TypeScript into CloudFormation

> **Author:** Prem Vishnoi &lt;pvishnoi@avilx.com&gt;
> **Section:** 2 — App, Stack, Construct
> **Duration:** 12:00

## Prereqs

L07 — `cdk init`

## Key terms

- **`cdk synth`** — the command that converts your CDK tree into one
  CloudFormation template per stack.
- **`cdk.out/`** — the output directory. One template JSON per stack
  + asset manifests.
- **`cdk diff`** — preview the changes a `cdk deploy` would make.
- **`--quiet`** — suppress the long CloudFormation output.

## Lecture

`cdk synth` is the bridge between your TypeScript code and
CloudFormation. It walks the construct tree and asks each
construct to contribute a CloudFormation resource. The result is a
template that any CloudFormation tool can read — including the
AWS Console.

```bash
cd 02_app_stack_construct/code/hello-cdk

npx cdk synth HelloCdkStack --quiet     # one stack
# → emits cdk.out/HelloCdkStack.template.json

npx cdk synth --quiet                   # all stacks in the app

ls cdk.out/
# HelloCdkStack.template.json
# manifest.json
# tree.json
```

The template is real CloudFormation. You can deploy it manually:

```bash
npx cdk synth | tee /tmp/cfn.json
aws cloudformation deploy \
  --template-file /tmp/cfn.json \
  --stack-name manual-hello-bucket
```

…but you should never do that. `cdk deploy` does the same thing
with better tracking, asset uploads, and tag propagation.

**Piping `cdk synth` through `jq` is the secret weapon**:

```bash
# how many resources will we deploy?
npx cdk synth --quiet | jq '.Resources | length'

# what types of resources?
npx cdk synth --quiet | jq -r '.Resources | to_entries[]
  | .value.Type' | sort | uniq -c
```

```text
   1 AWS::CDKMetadata::Condition
   1 AWS::S3::Bucket
   1 AWS::S3::BucketPolicy
   1 Custom::CDKBucketDeployment
```

The `BucketPolicy` is auto-generated by the L2 `s3.Bucket` because
of `autoDeleteObjects: true`. That kind of transparency is what makes
L2 ≫ L1 in day-to-day work.

## Hands-on

```bash
cd 02_app_stack_construct/code/hello-cdk
npm install
npx cdk synth --quiet | jq '.Resources | to_entries[].value.Type'
```

You should see four resource types. Now flip `versioned: false` in
`lib/hello-cdk-stack.ts` and re-synth — the output should be one
resource shorter (no `VersioningConfiguration`).
