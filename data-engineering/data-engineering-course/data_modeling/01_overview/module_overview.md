# Module 01 — Data Modeling Interview Overview

> **4 lessons · 1 video · ~30 min**
>
> **Author:** Prem Vishnoi &lt;pvishnoi@avilx.com&gt;

The data modeling interview is one of the four major rounds in a data
engineering loop. It is also the round that *most* candidates
under-prepare for, because it looks like a SQL test but it is actually
a structured conversation about ambiguity, grain, and tradeoffs.

This module gives you the shared vocabulary used in every later
module. Skim it once now; refer back to it as you read.

## Why this module is "design only"

There is no code in this module. The first four lessons are *thinking*
lessons — they establish the shared vocabulary and the rubric. Code
shows up in Module 02 (the requirements doc helper) and Module 03
(the five star schemas).

If you already know what a star schema is, you can skim this module
in 10 minutes and move to Module 02. If you don't, this is the
cheapest place in the track to learn it.

---

## How the track is structured

The data modeling round tests four things, in order:

1. **Discovery** — can you ask the right questions before drawing?
2. **Diagramming** — can you turn the answers into an ER diagram and
   then a star schema?
3. **Tradeoffs** — can you defend your SCD choice, your fact grain,
   your partitioning?
4. **Narration** — can you talk while you draw?

Modules 02–05 build the *content* of your answer (requirements →
diagrams → dimensions → facts). Module 06 layers performance on top.
Module 07 is the practice round, with three full mock interviews and
three written-up problems you can do on your own.
